# AltPane

AltPane is a Windows desktop task switcher that replaces the built-in Alt+Tab UI while it is running. It lists the windows that would normally appear in Alt+Tab, on every connected monitor at once, and stays open when you release the trigger key. Enter, or a click, switches to the selected window. There is no live thumbnail.

The interface follows the Windows display language when it is Chinese, and can be switched between Simplified Chinese and English in Settings.

## Features

- Low-level keyboard hook overrides Alt+Tab and Alt+Shift+Tab. By default, releasing the trigger key leaves the switcher open (sticky mode). Enter or a click activates the selected window. Esc, or a click outside the switcher, cancels and restores the previous foreground window. Classic release-to-switch is a setting.
- The hotkey is configurable. Win+Tab opens AltPane as well, unless that setting is turned off. A settings file written by 0.1.0 stored Win+Tab as off because that was the old implicit default. Loading that file turns Win+Tab capture, sticky mode, and the other 0.2 defaults on, and keeps the hotkey, theme, exclusions, and startup choice. A file that already contains `stickySwitcher` keeps an explicit off. The schema version is then stamped as 8. Settings shows whether Win+Tab is on or off. `showPreview`, `previewMinimized`, and `showOtherMonitorHints` from older files are ignored and left out of the next save. A file that was still on the old default, initial letter or stable grouped, moves to Focus time. An explicit Recent, app name, CPU, or memory choice stays. App name is still in the sort list, and choosing it again keeps it.
- The switcher lists visible top-level windows in Z-order, with icon, title, and process name. Tool windows, cloaked UWP ghosts, owned popups, and a small shell-class denylist are filtered out. ApplicationFrameHost windows use the hosted CoreWindow for the real process name, icon, and “end task” target.
- Type-to-search filters by window title or process name (substring, acronym, and pinyin). After the trigger key is released, the search box takes keyboard focus, so an IME can compose without Ctrl+F. Esc clears the search box when it has text and leaves the caret there; a second Esc, or Esc on an empty box, cancels. While a Chinese IME has a real composition string, the first Esc goes to the IME and does not clear the query or close the switcher. An IME that is only focused, or a key marked ImeProcessed with an empty composition, does not count. This is the same while Alt is held, after release in sticky mode, and in a Win+Tab session. The hook takes that Esc itself, so clearing and closing do not depend on the switcher being the foreground window. Every Esc while the switcher is open or still visible is written to `%APPDATA%\AltPane\altpane.log` at INFO. An IME candidate window does not count as a click outside. If the window is still visible after the open flag was cleared, Esc still clears or closes.
- The same box also launches installed apps, in the style of Listary. Open windows stay first. A separate Launch section lists matching Start Menu shortcuts, Microsoft Store apps, and desktop shortcuts (PATH executables are optional and off by default). `vsc` matches Visual Studio Code; `wx` or `weixin` matches 微信. Enter launches the app and closes the switcher, or switches to it when a window is already open (shown with an Open badge). Ctrl+Enter runs it as administrator. The context menu can open the file location. The index is built in the background at startup, cached in `%APPDATA%\AltPane\apps.json`, and refreshed by a shortcut watcher plus a full scan every 30 minutes, so opening the switcher never waits on it. A folder that cannot be opened, including the hidden Chinese Start Menu junction `程序`, is skipped. That does not discard the rest of the Start Menu, the common Start Menu, desktop, PATH, or Store apps. After each full scan the log records how many entries came from the Start Menu, desktop, PATH, and Store. How often you launch or switch to an app is stored in `launches.json` and nudges ranking when match quality is close. An empty query lists windows only.
- If [Everything](https://www.voidtools.com/) is running, a query with no matching window also asks it for `exe`, `lnk`, `url`, and `appref-ms` files. Results are not written into `apps.json`. Start Menu and desktop names win over a raw executable with the same target. Installer, WinSxS, temp, and `node_modules` paths are skipped. Everything’s own query is a literal filename match, so `wx` will not find `微信.exe` there; the built-in index still matches pinyin. If Everything is missing or stopped, the built-in index is used and the log records that once. The Launch heading then notes that Everything is not running. Settings can start it, change the extensions, and add folders to skip. Typing is debounced and a hung Everything is abandoned after a short timeout.
- While the switcher is open it shows machine CPU and memory, and each task’s CPU and working set. The row order is fixed when the switcher opens, and every monitor shows that same order. The default is Focus time (按使用时长). The first row is the most recent window you switched to yourself, other than the one in front, so Alt+Tab and then Enter — or a quick tap, when that setting is on — returns to it. Alt+Shift+Tab selects the last row. The opening key does not advance again, because that first row is already the previous window. The window that was in front stays in the list. A foreground change counts only when a key or click landed within about half a second before it, or when AltPane itself activated the window, and only after that window stays in front for at least a second. A VPN or tray popup that grabs the foreground and is dismissed does not become the previous window and does not earn focus time. Decayed focus minutes, with a 7-day half-life, are stored in `%APPDATA%\AltPane\usage.json`. Apps at or above the threshold (10 minutes by default; Settings offers 1, 5, 10, and 30) and pinned apps form the main list, ordered by that recent-use history. A pin keeps an app in the main list; it does not jump ahead of a window you used more recently. Apps below the threshold, apps you demote, and a built-in list of VPN and tray tools (飞连 / CorpLink, Clash, v2rayN, OpenVPN, GlobalProtect, Cisco AnyConnect, and a few similar names) stay under a Rarely used separator, also in recent-use order, and never take the first row while a main-list window exists. An app drops out of the main list only after it falls below 80 percent of the threshold. For the first day, and whenever there is no usage yet, an app stays in the main list and the order follows Z-order, so the first launch does not push every window down. Ctrl+Shift+P pins the selected app, Ctrl+Shift+B demotes it, and Ctrl+Shift+U restores the default. The same commands are on the row menu, and both lists are editable in Settings. The order is fixed when the switcher opens. An explicit pin or demote applies immediately. Search still finds every window, including demoted ones. Recent, app name, CPU, and memory are still in the sort control. A settings file on the old default, initial letter or stable grouped, moves to Focus time. An explicit Recent, app name, CPU, or memory choice is kept. Schema 7 adds `pinnedApps`, `demotedApps`, and `focusThresholdMinutes`. Schema 8 adds the frequent-apps sidebar (`showFrequentSidebar`, `frequentSidebarCount`, `sidebarPinnedApps`, `sidebarHiddenApps`). Each row shows an index taken from the application name: Chrome is c, and 微信 is wx. The first window of an application keeps that code and the next windows add 2, 3, and so on. Typing the code selects that first window. A shared prefix between different applications still grows by one more letter. The index stays until the next time the switcher opens. Arrow keys, Tab, and the wheel stop at the first and last row. Later samples update the numbers and the heat bar in place and do not reorder, rebuild, or move the selection. The list is sorted again only when you change the sort, and the selected window stays selected. A window that closes is removed where it was, and the selection moves to the neighbor. A window that opens while the switcher is visible waits until the next time you open it, so it is never inserted in the middle. Search hides non-matching rows and keeps the remaining ones in that same order; clearing the search puts the hidden rows back. Helper processes are rolled into the window that owns them (browsers, and UWP apps hosted by ApplicationFrameHost). Heavy tasks get a warm or hot bar. Sort by focus time, recent use, application name, CPU, or memory. Sampling runs on a background thread only while the switcher is visible.
- Keyboard and mouse navigation, plus close, end task on each row, minimize, maximize, and restore. Space activates the selected window, including one that is minimized. Nothing is moved off-screen for a preview.
- The same switcher is shown on every monitor at once, per-monitor DPI aware (v2). One list, one selection, one search box, and the same index badges and load numbers. Typing or moving the selection on any monitor updates the others. The keyboard starts on the monitor under the cursor, or the monitor of the active window. A click on a row in any copy activates that row.
- With more than one monitor, each row’s badge is relative to the monitor that copy is on. A window already on that monitor reads “This screen” (当前屏幕). Otherwise the badge is that window’s display number. The number is the Windows `\\.\DISPLAYn` index from `EnumDisplayMonitors` when those indexes are unique, and left-to-right then top-to-bottom otherwise. The same numbering is used on every copy. A window that spans displays uses the one with the largest overlap. A minimized window uses its restore position. The color follows the window’s display. Ctrl+Shift+D, or the This display button, lists only the windows on the copy that has the keyboard. One monitor, or the setting, hides the badges.
- Choosing a window moves it onto the monitor you used: the copy you clicked, or the monitor under the mouse when you press Enter. Position and size are scaled to the target work area, so a DPI change is not applied twice. A maximized window stays maximized. A minimized window restores there, or maximizes if it was maximized before it was minimized. A window snapped to an edge is snapped the same way on the target. Shift+Enter, or the context menu “Switch without moving”, leaves it where it is. “Move to this display” moves it even when the setting is off. A window AltPane cannot move (elevated, or exclusive fullscreen) is still activated. An app launched from search is moved onto that monitor if its window appears within a few seconds.
- System tray menu: open the switcher, Settings, pause/resume the override, start with Windows, exit. A second launch asks the running instance to open Settings.
- Settings are stored as JSON in `%APPDATA%\AltPane\settings.json`. A corrupt file is copied to `settings.json.bak` and defaults are loaded.
- Pausing, exiting, or an unhandled exception removes the hook. If the process is killed, Windows drops the hook as well, so the native switcher works again.
- Switcher windows are created at startup, one per monitor, and kept hidden. A background hook keeps the window list up to date, so opening paints that list instead of constructing a new window or walking every process. Icons are cached per executable. Each open writes one INFO line to `%APPDATA%\AltPane\altpane.log`: hotkey→visible milliseconds, enumeration milliseconds, and the row count. The working set is logged at startup and every 30 minutes.

## Frequent apps sidebar (0.4.8)

Every switcher, on every monitor, has a narrow column on the left listing the apps you have actually used. Rank is real foreground time over a rolling 7 days, computed in the background so opening stays as fast as before. Icons are cached ahead of time. Demoted apps, the built-in VPN and tray list, AltPane itself, and windows that grab the foreground on their own are excluded. Each item shows an icon, a short name, and a dot when a window is open. A click, or F1–F8 (Alt+F1–F8 while Alt is held), activates that app's most recent window, or launches the exe or shortcut stored with the stats. Right-click can pin, unpin, or hide an item. Pins stay first, in the order you set. The column stays in that order while the switcher is open. Arrow keys still move only the main list, and a resting pointer does not highlight a row during keyboard navigation. Ctrl+1–0 and the Ctrl+Enter / Ctrl+Shift+Enter / Ctrl+C shortcuts are unchanged. Settings schema 8 adds 显示常用应用侧栏 (on by default), the item count (6, 7, or 8), and the pin and hide lists. See [RELEASE_NOTES_v0.4.8.md](RELEASE_NOTES_v0.4.8.md).

## Search encoding, transport, and the file index (0.4.7)

Chinese paths from Everything's HTTP JSON stay Chinese on the secondary line. The body is decoded as UTF-8 (or an explicit Unicode charset), and the search is percent-encoded as UTF-8. IPC uses the Unicode query and list only. A transport counts as connected only after a reply message arrives, so the tray window's empty `WM_COPYDATA` no longer hides a working `http:8080`. The built-in index does not walk the disk while Everything is reachable. Its watcher ignores AltPane's own files and AppData, applies single-path updates, and waits at least five minutes after a buffer overflow before a full rescan. File rows show the row number only. See [RELEASE_NOTES_v0.4.7.md](RELEASE_NOTES_v0.4.7.md).

## Built-in file index and Win key (0.4.6)

File search still asks Everything first (IPC, then the tray and main windows, then the local HTTP server). When Everything is not running or does not answer, AltPane searches a built-in index instead. That index is on by default and does not need administrator rights. A background thread at low priority scans `%USERPROFILE%`, skipping hidden and system directories, `AppData`, and the same agent folders as Everything (`.gemini`, `.claude`, `.cursor`, `node_modules`, and the rest). Desktop, Documents, Downloads, Pictures, Videos, Music, OneDrive, and the Start Menu folders are included when they sit outside that walk. Settings can add more folders. The exclusion list is the one already used for Everything. File names and a parent-directory table are kept in memory, and a snapshot is stored in `%LOCALAPPDATA%\AltPane\file-index.bin` so the next start can search before the scan finishes. `FileSystemWatcher` applies changes after a short debounce, and a full rescan runs if the watcher buffer overflows. Search is a case-insensitive substring, AND across words, plus pinyin initials. Document types and the `f ` / `file:` prefix are unchanged. The file group is labeled 内置索引 or Everything. Each scan logs its duration, entry count, and memory at INFO.

A second setting, off by default, is 单按 Win 键打开 AltPane. A Win press and release with no other key in between opens an app list (Start Menu shortcuts and Store apps, with icons) instead of the Start menu. The Win key-up is swallowed and an unassigned key (VK_E8) is injected so Windows does not open Start. Win+E, Win+R, Win+D, Win+Shift+S, and the other Win shortcuts are unchanged. Type to filter by name or pinyin initials. Enter launches. Ctrl+Shift+Enter runs as administrator. Esc closes. Alt+Tab is unchanged. See [RELEASE_NOTES_v0.4.6.md](RELEASE_NOTES_v0.4.6.md).

## File search (0.4.5)

Typing in the switcher asks a running [Everything](https://www.voidtools.com/) 1.4 instance for documents. The default types are doc, docx, xls, xlsx, ppt, pptx, pdf, txt, md, csv, rtf, odt, ods, odp, wps, et, dps, ofd, and epub. `f ` or `file:` searches every type. Results sit in their own group, at most 20, sorted by Everything's run count.

AltPane sends the documented `WM_COPYDATA` query to `EVERYTHING_IPC_WNDCLASS`. On some 1.4 installs that class does not exist (not even as a message-only window) while the tray class `EVERYTHING_TASKBAR_NOTIFICATION` does, and there is no `Everything64.dll` or `es.exe`. The same query is then sent to the tray window and, if Everything's main window is open, to `EVERYTHING`. A reply has to arrive before the timeout; an empty list counts, silence does not. If IPC never answers, AltPane queries Everything's HTTP server on localhost (`/?search=…&json=1&path_column=1&count=N`), port 80 by default and then 8080. Settings changes the port and can turn the 8080 retry off. The request runs on a background thread.

The switcher and Settings say which state it is: Everything is not running, Everything is running but IPC failed (enable **选项 → HTTP 服务器** in Everything), or connected over HTTP. The transport is logged at INFO (`file search N ms, rows N, transport http:80`).

File search always skips agent work directories with `!path:` terms, and drops any row that still comes back: `.gemini`, `.claude`, `.cursor`, `.codex`, `.copilot`, `.continue`, `.aider*`, `.ollama`, `.lmstudio`, `.windsurf`, `.codeium`, `.qwen`, `.kimi`, `.trae`, `.vscode\extensions`, and `node_modules`. Extra folders from Settings are added the same way. See [RELEASE_NOTES_v0.4.5.md](RELEASE_NOTES_v0.4.5.md).

To use the HTTP workaround in Everything: Tools → Options → HTTP Server → Enable HTTP server. Port 80 often needs an administrator. If it will not listen, set Everything's port to 8080. AltPane tries 8080 after 80, and the HTTP port in AltPane Settings can be 8080 directly.

| Activate with the mouse | Click a row |

A very fast Alt+Tab, released before the window is drawn, leaves the switcher open in the default sticky mode. Settings has “Still switch on a very quick tap” for the old behavior: that tap activates the previous window without flashing the switcher. Classic mode (sticky off) always does that.

While the trigger is held, typed characters are read with `ToUnicode` and the Alt bits cleared. That path is for Latin letters, digits, and symbols (process names and English titles). Releasing the trigger focuses the real search box and passes keys through, including IME composition. Ctrl+F or a click on the search box does the same thing before the key is released. Press Enter to switch. The hook swallows the activation chord, and it does not swallow the keys the search box needs.

If the hotkey itself includes Shift, Shift does not reverse direction. Use the arrow keys.

## Run

Two win-x64 builds are published.

The smaller one is framework-dependent. Install the .NET 8 Desktop Runtime (x64) first, then run `AltPane.exe`. Download it from [dotnet.microsoft.com/download/dotnet/8.0](https://dotnet.microsoft.com/download/dotnet/8.0) (Desktop Runtime, Windows x64) or the direct installer: <https://aka.ms/dotnet/8.0/windowsdesktop-runtime-win-x64.exe>.

The self-contained build includes the runtime. Copy `AltPane.exe` to a Windows 10 or Windows 11 x64 machine and start it. No separate .NET install is required. The first launch unpacks native libraries and is slower than later launches.

Windows SmartScreen may warn because the executable is unsigned. Choose “More info”, then “Run anyway”, if you trust the binary you built.

AltPane starts in the notification area. The first launch shows a balloon. Right-click the icon for Settings, pause, startup, and exit. Left-click opens the switcher without stealing Alt+Tab (Enter confirms, Esc cancels).

A normal (non-admin) process cannot activate some elevated windows. Settings has **Restart as administrator**. The manifest stays `asInvoker`, so everyday use does not require elevation.

Startup registration writes the quoted path of the real executable to `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` under the value `AltPane`. A winget portable alias, or any other symlink used to start AltPane, is resolved with `File.ResolveLinkTarget` before that path is stored or used to restart as administrator.

Logs: `%APPDATA%\AltPane\altpane.log` (rotated to `altpane.log.old` around 1 MB). Startup records whether Win+Tab capture is on. Settings can also log each Win and Tab the hook sees. The tray menu has “Open log folder”.

The app index is `%APPDATA%\AltPane\apps.json`. Launch counts and last-used times are `%APPDATA%\AltPane\launches.json`. Decayed focus time for the default sort is `%APPDATA%\AltPane\usage.json`, rewritten a few seconds after it changes. Both are rewritten only after the background scan changes, so the first Alt+Tab after startup reads whatever is already in memory. Settings choose the sources (Start Menu, Store, Desktop, PATH) and an exclusion list. A name matches the display name, process name, or file name. A token that contains `\` or `/` hides every app under that folder. PATH indexing skips `Windows\System32`, `SysWOW64`, and `WinSxS`. Duplicate targets keep the Start Menu or Store name over a desktop shortcut.

## Build

Requires the .NET 8 SDK. On Windows:

```powershell
dotnet test tests/AltPane.Tests/AltPane.Tests.csproj -c Release
dotnet publish src/AltPane/AltPane.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

`publish\AltPane.exe` is the self-contained app. `build.ps1` runs the same two commands.

Framework-dependent single file (requires the .NET 8 Desktop Runtime linked above):

```powershell
dotnet publish src/AltPane/AltPane.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o publish-fx
```

The WPF project sets `EnableWindowsTargeting`, so the same publish command also works on Linux when the Windows desktop targeting pack can be downloaded. The UI cannot be executed there.

## Layout

- `src/AltPane.Core` — net8.0 library with no UI: window-filter rules, search (including the embedded pinyin table), the installed-app catalog and shell-link parser, the hook gesture state machine, settings load/save, switcher session, localization tables, and native struct sizes.
- `src/AltPane` — WPF app (plus a WinForms tray icon): the low-level hook, window enumeration, one switcher window per monitor, and settings.
- `tests/AltPane.Tests` — xUnit tests for the core library.

The hook procedure only classifies the key and queues a small operation. Enumeration and UI work run on the dispatcher, so the hook stays inside Windows’ low-level hook timeout. The delegate is rooted for the lifetime of the service. Pause and exit call `UnhookWindowsHookEx`.

## Known limitations

- Win+Tab is taken by the low-level hook: Tab is not delivered, and an unassigned key (VK_E8) is injected while Win is still down so the later Win key-up does not open Start. Both Win keys are then released, so the Windows key is not left stuck. A low-level hook in a process that is not elevated does not see keystrokes while an elevated window is in front. Win+Tab then falls through to Task View until AltPane is restarted as administrator.
- Switching to an elevated window, or closing it, can fail with UIPI unless AltPane is running as administrator.
- “Other virtual desktops” is approximate. The shell cloak bit and `IVirtualDesktopManager` are used when available. The application cloak bit (UWP ghost windows) is always hidden.
- Protected processes (`explorer`, `csrss`, `lsass`, `svchost`, `dwm`, and similar) and an unresolved ApplicationFrameHost window cannot be killed from the switcher. Ending an elevated process needs AltPane to be running as administrator; the switcher says so when access is denied. CPU percent needs two samples, so the first fraction of a second shows memory and then CPU. GPU and disk load are not shown. Per-task CPU is a share of the whole machine. Memory is the working set, with private bytes in the tooltip, summed across helper processes.
- The switcher keeps `AllowsTransparency` off. The window fill is opaque. Windows 11 rounds it with `DWMWA_WINDOW_CORNER_PREFERENCE`; Windows 10 keeps square corners. The outer edge is a 2px accent plus a 1px contrasting hairline, and DWM draws the shadow from a one-pixel frame extension. Mica and acrylic are not used, because a transparent client paints black when those effects are unavailable. `WM_NCACTIVATE` is handled so the borderless client does not paint black when a copy loses focus. Every copy hides together.
- The single-file executable is unsigned.
- Store apps are discovered through `shell:AppsFolder` on a background thread and that scan is best-effort. If it fails, Start Menu and desktop shortcuts are still indexed. A Store app is launched with `IApplicationActivationManager`, then `explorer.exe shell:AppsFolder\<aumid>` if that fails. Store apps have no “run as administrator” and no file location.
- Match quality outweighs habit when the gap is large: an exact name beats a heavily used loose match. Frequent use can lift a prefix above a never-used exact name. Pinyin covers the common readings in the embedded table, not every rare character.

## 中文说明

AltPane 是一个 Windows 桌面窗口切换器。运行期间它会用低级键盘钩子接管 Alt+Tab（以及 Alt+Shift+Tab），系统自带的切换界面不会出现。Win+Tab 默认也会打开 AltPane，而不是任务视图；松开 Win 不会弹出开始菜单，也不会让 Windows 键卡住。单独按 Windows 键仍打开开始菜单（除非在设置里打开「单按 Win 键打开 AltPane」），Win+E、Win+D、Win+Shift+S 保持原样。默认松开触发键后切换器保持打开，Enter 或单击才切换到所选窗口，Esc 或点击外部取消。设置里可以改回松开即切换，也可以关闭 Win+Tab 接管。当前窗口以管理员身份运行时，需要同样以管理员身份启动 AltPane，钩子才能看到这个组合键。接了多台显示器时，每一台上都会同时出现完整的切换窗口，列表、选中项、搜索和负载数字是同一份。窗口就在这一台上时，标记为“当前屏幕”；否则显示那台显示器的序号，与 Windows 设置里的 1、2、3… 一致（`\\.\DISPLAYn` 编号唯一时，否则从左到右）。键盘落在鼠标所在的屏幕，或当前窗口所在的屏幕。在任意一份上单击一行都会激活它，并把窗口移到那一台（用键盘按 Enter 时移到鼠标所在的屏幕）。只有一台显示器时不显示屏幕标记。Ctrl+Shift+D 或“本显示器”按钮只列出当前拥有键盘的那一台上的窗口。

界面默认跟随系统语言：中文系统使用简体中文，也可在设置里改为 English。设置保存在 `%APPDATA%\AltPane\settings.json`。托盘图标可以打开切换器、设置、暂停接管、开机启动和退出。程序崩溃、暂停或结束后会卸下钩子，原生 Alt+Tab 恢复可用。

启动时就会为每台显示器建好切换窗口并保持隐藏，窗口列表由后台钩子增量维护。按下 Alt+Tab 后直接显示这份列表，而不是新建窗口或在打开时遍历每个进程。图标按可执行文件缓存。每次真正打开都会用一行 INFO 记下从热键到窗口可见的毫秒、枚举毫秒和行数。工作集在启动时和之后每 30 分钟各记一行，日志在 `%APPDATA%\AltPane\altpane.log`。

按住 Alt 时直接打字适合英文和进程名。松开 Alt 后搜索框会获得焦点，可以直接用中文输入法，再按 Enter 确认；按住时仍可用 Ctrl+F。搜索框里有文字时，Esc 先清空搜索并回到清空前选中的窗口，光标仍留在搜索框；再按一次 Esc，或搜索框本来就是空的，才退出切换器。中文输入法确实在组字（组字串非空）时，第一次 Esc 只取消组字，不会清空搜索，也不会关闭切换器。仅仅焦点在输入法上、或组字串为空，都不算组字。按住 Alt、松开后的粘滞模式，以及 Win+Tab 打开的会话都是这样。切换器可见时钩子直接处理 Esc，不依赖切换器是否处于前台。切换器打开或窗口仍可见时，每一次 Esc 都会以 INFO 写入 `%APPDATA%\AltPane\altpane.log`。输入法候选窗不算点击外部。若窗口还在而打开标记已被清掉，Esc 仍然会清空或关闭。窗口列表默认按使用时长排序。第一行是你自己切换到过的上一个窗口（不是当时在前台、也不是自己弹出来的那个），所以 Alt+Tab 再按 Enter（或开启“轻点即切换”时的快速点按）会回到它。Alt+Shift+Tab 选中最后一行。打开的那一下不会再往下移，因为第一行已经是上一个窗口。当时在前台的窗口仍留在列表里，不会被藏起来。只有你在它成为前台之前约半秒内按过键或点过鼠标，或者是 AltPane 自己激活的，并且它在前台停留至少一秒，才算一次使用。自己抢前台又马上消失的窗口（例如飞连）不会变成“上一个窗口”，也不会计入使用时长。使用时长按大约 7 天的半衰期衰减，存在 `%APPDATA%\AltPane\usage.json`。达到阈值（默认 10 分钟，设置里可选 1、5、10、30）的应用，以及置顶的应用，组成主列表，按最近使用排列。置顶只保证留在主列表，不会插到比它更近使用过的窗口前面。低于阈值的、你手动降低的，以及内置的 VPN 和托盘工具（飞连 / CorpLink、Clash、v2rayN、OpenVPN、GlobalProtect、Cisco AnyConnect 等）排在“不常用”分隔线下面，同样按最近使用，并且只要还有主列表窗口就不会占第一行。要掉出主列表，需要降到阈值的 80%，避免来回跳动。第一天、以及还没有使用记录时，应用留在主列表并按 Z 序排列，所以第一次打开不会把所有窗口都压到后面。Ctrl+Shift+P 置顶，Ctrl+Shift+B 降低优先级，Ctrl+Shift+U 恢复默认，右键菜单和设置里也可以改。打开时的顺序是固定的；当场置顶或降低会立刻重排。搜索仍能找到被降低的窗口。最近使用、应用名、CPU 和内存仍可在排序里选择。原先使用默认的首字母排序或稳定分组的设置会迁到按使用时长；已经选过最近使用、应用名、CPU 或内存的保持不变。设置架构 7 增加 `pinnedApps`、`demotedApps` 和 `focusThresholdMinutes`。设置架构 8 增加常用应用侧栏（`showFrequentSidebar`、`frequentSidebarCount`、`sidebarPinnedApps`、`sidebarHiddenApps`）。每一行左侧是应用名索引：Chrome 是 c，微信是 wx。同一应用的第一个窗口用这个索引，后面的窗口加上 2、3。输入该索引会选中该应用的第一个窗口。不同应用的前缀相同就再加一个字母。本次打开期间索引不变。方向键、Tab 和滚轮停在第一行和最后一行，不会绕回。点到任意一份切换窗口以外会把每一份都关掉。没有实时预览，也不会为了预览把最小化窗口挪到屏幕外。切换器外圈是两像素强调色加一像素对比细线。

搜索框同时可以启动已安装的应用：窗口仍排在前面，下面是“启动”分组。`vsc` 能找到 Visual Studio Code，`wx` 或 `weixin` 能找到微信。Enter 启动应用并关闭切换器；若该应用已有窗口，会标明“已打开”，Enter 改为切换过去。Ctrl+Enter 以管理员身份运行（商店应用不可以）。右键可打开文件所在位置。索引在后台建立，缓存在 `%APPDATA%\AltPane\apps.json`，使用次数在 `launches.json`，打开切换器不会等待扫描。打不开的文件夹会被跳过，包括中文开始菜单里的隐藏联接 `程序`，不会因此丢掉公共开始菜单、桌面、PATH 或商店应用。每次完整扫描会用一行 INFO 记下开始菜单、桌面、PATH 和商店各自的条目数。默认索引开始菜单、商店应用和桌面快捷方式，PATH 默认关闭。搜索框为空时不列出全部应用。若本机正在运行 [Everything](https://www.voidtools.com/)，没有匹配窗口的查询还会查找 `exe`、`lnk`、`url`、`appref-ms`。这些结果不会写入 `apps.json`。开始菜单和桌面上的名称优先于同一目标的原始可执行文件。安装包、WinSxS、临时目录和 `node_modules` 会被跳过。Everything 自己的查询是文件名的字面匹配，所以 `wx` 找不到 `微信.exe`；内置索引仍然支持拼音。Everything 未安装或未运行时，只用内置索引，并只记一行日志。启动分组会提示“Everything 未运行，使用内置索引”。设置里可以启动它、修改扩展名，以及增加要跳过的文件夹。输入会防抖，Everything 卡住时会在短时间后放弃。没有匹配窗口时，最上面的启动项会被预先选中，Enter 即启动。

文件搜索优先走 Everything。0.4.5 在找不到 `EVERYTHING_IPC_WNDCLASS` 时，会把同一条 `WM_COPYDATA` 查询发给托盘窗口 `EVERYTHING_TASKBAR_NOTIFICATION`，再发给主窗口 `EVERYTHING`，并在超时内确认有没有回应。IPC 都失败时改查本机 HTTP 服务器（默认端口 80，可再试 8080，设置里可以改）。界面会区分「Everything 未运行」、「Everything 在运行但 IPC 连接失败」（请到 Everything 的选项 → HTTP 服务器 中启用）和「已通过 HTTP 连接」。实际用的传输以 INFO 写入日志。用户目录下的代理工作目录（`.cursor`、`.claude`、`.gemini`、`.aider*`、`.vscode\extensions` 等）和 `node_modules` 会用 `!path:` 排除，设置里的额外文件夹仍然生效。在 Everything 中打开 HTTP：工具 → 选项 → HTTP 服务器 → 启用 HTTP 服务器。80 端口常常需要管理员；起不来就改成 8080。详见 [RELEASE_NOTES_v0.4.5.md](RELEASE_NOTES_v0.4.5.md)。

0.4.6 在 Everything 连不上时改用内置文件索引（默认开启，不需要管理员）。后台低优先级扫描用户目录，跳过隐藏和系统目录、AppData，以及上面的代理目录；桌面、文档、下载、图片、视频、音乐、OneDrive 和开始菜单会另外纳入。名字和父目录表放在内存里，快照在 `%LOCALAPPDATA%\AltPane\file-index.bin`。文件变化由 `FileSystemWatcher` 防抖更新，缓冲区溢出就整目录重扫。搜索不区分大小写，多个词是 AND，中文名可以用拼音首字母。`f ` 和文档类型过滤不变。结果分组标成「内置索引」或「Everything」。设置里可以关掉内置索引、追加文件夹，排除列表沿用原来的那一份。扫描耗时、条数和内存记在 INFO。

另有一项默认关闭的设置「单按 Win 键打开 AltPane」。只按下再松开 Win、中间没有别的键，会打开应用列表（开始菜单快捷方式和商店应用，带图标），而不是开始菜单。Win 的松开被吃掉，并注入一个未分配键（VK_E8），所以开始菜单不会弹出。Win+E、Win+R、Win+D、Win+Shift+S 以及其他组合键不变。输入名称或拼音首字母过滤，Enter 启动，Ctrl+Shift+Enter 以管理员运行，Esc 退出。Alt+Tab 的行为不变。详见 [RELEASE_NOTES_v0.4.6.md](RELEASE_NOTES_v0.4.6.md)。

0.4.8 在每台显示器的切换器左侧加上常用应用侧栏。名次按最近 7 天的真实使用时长计算，在后台算好，图标也提前缓存，所以打开不会变慢。降低优先级的应用、内置 VPN、AltPane 自己，以及自己抢前台的窗口不会出现。每一项显示图标和短名称，有窗口时带一个小圆点。单击或 F1–F8（按住 Alt 时为 Alt+F1–F8）会切到该应用最近的窗口，没有窗口就启动统计里记下的程序或快捷方式。右键可以固定到侧栏、取消固定或从侧栏移除。固定项按你的顺序排在前面。切换器开着时侧栏顺序不变，方向键仍然只移动主列表。设置里可以关闭侧栏、把数量改成 6、7 或 8，并编辑固定和隐藏名单。设置架构 8。详见 [RELEASE_NOTES_v0.4.8.md](RELEASE_NOTES_v0.4.8.md)。

极快地按一下 Alt+Tab 默认也会保持打开，设置中可改为立即切换。切换器打开时会显示整机和每个任务的 CPU、内存。打开那一刻的顺序（按使用时长、最近使用、应用名、CPU 或内存）会被固定，每台显示器上的顺序相同，之后只更新数字和热度条，不再重排，选中项也不会跳。只有改排序方式时才会重新排一次，并保持当前窗口仍被选中。窗口关闭后就地移除，选中移到相邻项。切换器开着时新出现的窗口要等下次打开才进入列表，不会插到中间。搜索只按这个顺序隐藏不匹配的行，清空后顺序不变。Shift+Delete 结束任务（可在设置中要求再按一次确认，并结束子进程）。搜索框为空时，空格会激活所选窗口，包括已经最小化的窗口。

在某一份切换窗口上选中另一个屏幕上的窗口时，会先把它移到那一份所在的屏幕再激活；用键盘按 Enter 时，目标是鼠标所在的屏幕。位置和大小按工作区比例缩放，DPI 不会被乘两次。最大化的窗口在目标屏幕上仍最大化，最小化的窗口在那里还原。Shift+Enter 或右键“不移动并切换”保持原位。“移到此显示器”即使设置关闭也会移动。无法移动的窗口（权限更高，或独占全屏）仍会尝试激活。从搜索启动的应用若在几秒内出现在别的屏幕上，也会尽量移到你使用的那一台。这项默认开启，可在设置中关闭。

0.1.0 保存的设置把 Win+Tab 记成关闭。0.3.0 第一次加载这种还没有 `stickySwitcher` 的文件时，会打开 Win+Tab 接管、粘滞模式和其他 0.2 的默认项，并保留热键、主题、排除项和开机启动。已经包含 `stickySwitcher` 的文件如果明确关闭了 Win+Tab，会保持关闭。设置里会显示“Win+Tab: 开/关”，启动时写入 `%APPDATA%\AltPane\altpane.log`。托盘可以打开日志文件夹。设置里可以记录钩子看到的 Win 和 Tab。

开机启动写入的是真实 `AltPane.exe` 的路径。通过 winget 便携别名或符号链接启动时，会先解析链接再写入注册表。版本号、公司名（`kurlez`）和版权在 `Directory.Build.props`。发布步骤见 [RELEASING.md](RELEASING.md)。本项目采用 MIT 许可证，Copyright (c) 2026 Wenfeng Liu。

窗口填充是不透明的主题色。外圈是两像素强调色，里面再加一像素对比细线，亮色和暗色桌面都能看清。Windows 11 由系统裁成圆角，Windows 10 保持直角。阴影来自 DWM，不再把整窗做成透明玻璃，因此边角不会出现黑块。点到其他窗口会关掉每一份切换窗口，目标窗口不会变黑。普通权限无法切换或结束以管理员身份运行的窗口，需要在设置中“以管理员身份重新启动”。

较小的发布包依赖本机已安装的 .NET 8 桌面运行时（x64）：<https://dotnet.microsoft.com/download/dotnet/8.0> ，安装包直链 <https://aka.ms/dotnet/8.0/windowsdesktop-runtime-win-x64.exe>。自包含的 `AltPane.exe` 不需要另外安装运行时；首次启动会解压本机库，会稍慢。文件未签名，SmartScreen 可能提示，确认来源后选择仍要运行。
