# AltPane 0.4.15

## 中文

这一版修三个在 0.4.14 上看到的问题：文件对话框跳转把进程打崩、切换时目标窗口有时变成很小一块，以及托盘进程占了将近 200 MB。

- **崩溃。** 点旧式打开对话框跳转栏里的文件夹时，进程以 `AccessViolationException` 退出（`coreclr.dll` `0xc0000005`）。原因是 `WM_GETISHELLBROWSER` 拿到的 `IShellBrowser` 指针属于对话框那个进程，AltPane 却在自己的进程里读了它的虚表。这种访问违例抓不住。0.4.15 删掉这条路径。跳转只做本进程安全的事：文件名框写入以 `\` 结尾的路径再按确定，不行再改地址栏（UI Automation 或窗口消息）。公共项对话框和旧式对话框都是这个顺序。另存为仍把原来的文件名写回去。确定键只在读回的文本确实以 `\` 或 `/` 结尾时才发送。
- **日志。** 每一次尝试在 `Go` 返回之前就写入 `%APPDATA%\AltPane\altpane.log`，带窗口类、对话框种类、方法、路径和失败原因（例如 `edit-rejected`、`not-consumed`、`address-missing`、`address-unchanged`、`not-found`）。未处理的托管异常也会记成 `unhandled exception terminating=`。访问违例仍然抓不住，所以真正的修复是不再去读别的进程的指针。
- **窗口变小。** 激活不再对已经可见的窗口调用 `ShowWindow(SW_SHOW)`，也不再调用会把最大化 / 贴边窗口还原的 `SwitchToThisWindow(true)`。只有最小化的窗口才 `SW_RESTORE`。调整 Z 序的 `SetWindowPos` 带 `SWP_NOSIZE | SWP_NOMOVE`（大小参数是 0，不会被当成新尺寸），并且在目标窗口自己的 DPI 上下文里调用，避免每监视器 DPI 把别人的窗口缩小。并排窗口不再用一次 `DeferWindowPos` 同时改两个 DPI 不同的窗口。如果激活之后位置或大小还是变了，会按激活前的矩形放回去；最大化被取消时用 `SW_SHOWMAXIMIZED` 恢复，而不是写入一个过小的普通矩形。跨屏幕移动如果会把大窗口收成邮票大小，就放弃这次移动。激活前后的矩形写入 `altpane.log`（`Activate frame ... before ... after ... drifted=`）。
- **内存。** 在用户机器上，0.4.14 启动约 7 分钟后工作集约 211 MB、私有字节约 187 MB（`file-index.bin` 只有 2.7 MB）。0.4.15 使用工作站 GC、关闭并发 GC，并设置 `System.GC.ConserveMemory=9`。切换器隐藏后清掉已经实现的列表视觉树，图标缓存从 256 降到 96，并在几秒后做一次压缩 GC 加 `EmptyWorkingSet`。文件监视缓冲区从 64 KB 降到 16 KB。线程池最小线程数降到 4。设置窗口、关于窗口和跳转条本来就是用到才创建。这里无法在 Windows 上复测那个数字；按代码估算，空闲私有字节应落在大约 70–110 MB，工作集在回收之后往往更低。启动和每 30 分钟的日志现在同时写工作集和私有字节。

## English

Three fixes for what 0.4.14 did on a real PC: the file-dialog jump crashed the process, switching sometimes shrank the target window, and the tray process sat near 200 MB.

- **Crash.** Clicking a folder in the jump bar of a legacy Open dialog killed the process with `AccessViolationException` (`coreclr.dll` `0xc0000005`). `WM_GETISHELLBROWSER` returns an `IShellBrowser` pointer that belongs to the dialog's process. AltPane read its vtable locally. An access violation cannot be caught. 0.4.15 removes that path. A jump only uses in-process calls: write the folder into the filename box with a trailing `\`, press the default button, and if that misses, edit the address bar through UI Automation or window messages. Common-item and legacy dialogs share that order. A Save dialog still gets its previous filename back. The default button is pressed only when the text that was read back actually ends in `\` or `/`.
- **Log.** Each attempt is written to `%APPDATA%\AltPane\altpane.log` before `Go` returns, with the window class, dialog kind, method, path, and reason (`edit-rejected`, `not-consumed`, `address-missing`, `address-unchanged`, `not-found`, and so on). Unhandled managed exceptions are logged as `unhandled exception terminating=`. An access violation still cannot be caught; the fix is to stop reading another process's pointer.
- **Tiny windows.** Activation no longer calls `ShowWindow(SW_SHOW)` on a window that is already visible, and no longer calls `SwitchToThisWindow(true)`, which restores a maximized or snapped window onto `rcNormalPosition`. Only a minimized window gets `SW_RESTORE`. Z-order `SetWindowPos` uses `SWP_NOSIZE | SWP_NOMOVE` (the zero size is not applied) and runs in the target window's DPI awareness context, so a per-monitor-aware caller does not scale another process's window. A side-by-side pair is no longer positioned with one `DeferWindowPos` across two DPI contexts. If the frame still changes, it is put back to the rectangle from before the call; a window that lost its maximized state is restored with `SW_SHOWMAXIMIZED` rather than a tiny normal rect. A cross-monitor move that would stamp a large window down is skipped. The rectangle before and after is written to `altpane.log` (`Activate frame ... before ... after ... drifted=`).
- **Memory.** On the reported PC, 0.4.14 was about 211 MB working set and 187 MB private after seven minutes, while `file-index.bin` is 2.7 MB. 0.4.15 uses workstation GC, turns concurrent GC off, and sets `System.GC.ConserveMemory=9`. Hiding the switcher drops the realized row tree, the icon cache holds 96 images instead of 256, and a compacting GC plus `EmptyWorkingSet` runs a few seconds later. File-watcher buffers are 16 KB instead of 64 KB. The thread-pool minimum is 4. Settings, About, and the jump bar were already created on demand. This machine cannot remeasure that Windows process. From the code, idle private bytes should land around 70–110 MB, and the working set is often lower after the trim. Startup and the 30-minute line now log both working set and private bytes.
